# Context guard — technical notes (V6.9.1)

## Problem

`workflow.py plan` partitions a run into tasks with exclusive `paths` and optional `depends_on`. That is **ownership partitioning**. It does not create separate model contexts.

- `auto_runner.py` only spawns external CLI processes when `--approve-agents` (and usually `--approve-worktrees`) is given. Otherwise it prints `PREVIEW` and returns.
- `examples/agents.example.json` ships `demo-safe`, which prints a line and writes no code.
- `uw_internal_auto.py` and `uw_internal_team.py` are state machines executed by the **same host assistant**: `next_task()` explicitly says "The same host assistant performs the next role. No external AI is launched."
- `uw_internal_team.prompt()` returns `prior_evidence` for all previous roles; `uw_internal_auto.status` prints the whole state; `record()` accepts up to 50,000 chars per role; `markdown()` prints up to 2,000 chars per role per task; `workflow.gate()` stores 4,000 chars of stdout and 4,000 of stderr per check.

So context grows monotonically (and cumulatively quadratic if state is re-read each step). Measured on the real script with 12 tasks × 4 roles × 805-char evidence: state = 47,497 bytes; `status` output grows 3,277 → 46,584 bytes; 48 status reads total ≈ 1,196,796 bytes ≈ 299,000 estimated tokens (bytes/4), excluding source files, build output and reports.

## Design

`scripts/uw_context_guard.py` is read-only by default, stdlib only, no subprocess/network/model calls. It never modifies `plan.json`, git, or validation gates.

| Command | Behaviour |
|---|---|
| `brief --run RUN` | Reads `plan.json` + optional `internal-auto.json`; returns counts, one ready task (id, role, acceptance, paths, deps), blockers, one bounded verification snippet (≤180 chars), next command, and context rules. Never emits evidence bodies. |
| `check --run RUN --max-tokens N` | Sums `ceil(bytes/4)` over fixed policy docs, installed `SKILL.md` files, `commands/registry.json`, all run artifacts (excluding `FRESH_PROMPT.md` and `*.full.json`/`*.bak`) and `.ai/reports/*`. Returns `over_budget` and the top 10 files. Exit code **2** on over-budget. |
| `prompt --run RUN` | Writes `.ai/runs/RUN/FRESH_PROMPT.md` (≤450 words): what to read, what never to read, current task, scope, acceptance, last verification, blockers, next command, five mandatory rules. |
| `trim --run RUN --max-chars N [--apply]` | Preview by default. Copies the full state to `internal-auto.full.json`, then replaces over-long `evidence[role].details` with a bounded prefix + pointer. Marks `trimmed: true`. |

`state()` in `uw_internal_auto.py` validates only task IDs, `depends_on` and `acceptance`, so trimming evidence details does not break resume or dependency checks.

## Measured effect (same 12-task fixture)

| Metric | Before | After |
|---|---|---|
| Run-state view in chat | 47,497 bytes (`status`) | 839 bytes (`brief`) ≈ 56× smaller |
| Budget check | none | 31,672 estimated tokens > 12,000 → `over_budget: true`, exit 2 |
| Fresh-session prompt | none | 256 words ≈ 595 estimated tokens |
| Evidence trim | none | 48 entries, ≈21,360 chars saved, full copy preserved |

## Integration points

- `commands/registry.json`: new `uw-context`, updated `uw-auto`, `uw-team`, `uw-resume`. All platform files are generated by `scripts/generate_commands.py`; `--check` must report 0 out-of-sync before publishing.
- `AGENTS.md`, `.ai/CONTEXT_POLICY.md` (rule 10), `.cursor/rules/universal-workflow.mdc`, `.github/copilot-instructions.md`, `UW_AUTO_AR.md`, `INTERNAL_AI_TEAM_AR.md`, `V6_9_GUIDE_AR.md`, `README.md`, `README_AR.md`, `README_GITHUB.md`, `docs/COMMANDS_AND_SKILLS*.md`.
- `scripts/install_ai.py` → `RUNTIME_FILES` includes the guard, so `install_ai.py --platforms ...` copies it into target projects.
- `tests/test_uw_context_guard.py` covers compact brief, bounded prompt, budget check (including exit 2), trim preview/apply with backup, exclusion of backup/prompt from `check`, and path-traversal rejection.

## Limits

- Estimates are UTF-8 bytes/4 of **file sizes**, not tokenizer counts, provider billing, or live context usage. Hosts also inject their own system prompts and tool schemas, which this tool cannot see.
- `check` counts files that a host *might* load. Some hosts load only skill frontmatter; others load full bodies. Treat the number as a relative signal, not a quota.
- No tool can raise a provider quota. Real isolation requires a fresh chat per task or separate external CLI processes (separate provider cost).
- `generate_commands.py --check` on a partial install (`--platforms codex`) reports the other five platforms as out-of-sync because it compares against all six. This is a reporting limitation of the original command, unchanged in this release.
